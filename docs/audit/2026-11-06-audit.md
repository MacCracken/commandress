# commandress P-1 audit — 2026-11-06

**Scope**: the v1.2.2 codebase — all of `src/`, `adapters/`, `scripts/`,
`.github/workflows/` and `cyrius.cyml`. The vendored `lib/` snapshot stays out of scope as a
dependency, except how this repo calls into it, and except bayan's TOML and CYML sublibs and
cmdit, which were reviewed from the consumer side.

**Prior reports**: [2026-05-18](2026-05-18-audit.md) (v0.8.0) and
[2026-08-26](2026-08-26-audit.md) (v1.1.5). The second named what should trigger this one, and
all of it had happened: cmdit moved 1.2.4 → 1.5.0, bayan replaced the parser,
`rust-toolchain.toml` became the first repo-controlled input to reach that parser, and
`budget_ms` added a config field.

**Method**: three tracks.

1. **A parallel read** of the first-party code along five dimensions: memory discipline,
   untrusted bytes reaching a terminal or shell, the two dependencies from the consumer side,
   cache / filesystem / subprocess, and supply chain / CI. Each reviewer worked from a frozen
   1.2.2 snapshot, with no sight of the others, and had to try to refute each candidate.
2. **Live attack testing** of the built binary: real zsh and bash on a pty, a real VTE, a real
   FUSE wedge, a real second UID, fault injection into every `alloc`, and the `--agnos` build
   booted on a real kernel for the first time.
3. **An optimization pass** that measured first.

Every finding below was reproduced before it was fixed. Each fix was then proved by undoing it
and watching a gate go red: **48 of 48 mutations caught**. Three mutants survived the
first run, and each exposed a weak test, which is now fixed. The attacks were replayed on the
final binary.

A sixth reviewer then read the finished diff, with none of this reasoning, looking for what the
repairs broke, **and found real bugs in them**. The first draft of the bash wrap hung forever on a
non-SGR sequence in the user's own `trailer`, which would have locked them out of every new shell.
The first draft of the zsh adapter added a new command-execution channel under `glob_subst
glob_assign`. Neither reached a release, and both are now in `adapter-check.sh`. It is worth
recording that an attack matrix, 42 mutants and a clean differential had all missed them, because
each of those tests what the author thought of.

**Numbering**: **T-nn** untrusted bytes, terminal and shell. **R-nn** runtime: cache, filesystem,
subprocess. **M-nn** memory. **D-nn** dependencies and their callers. **SC-nn** supply chain and
CI. **O-nn** performance. The source comments cite these.

**Outcome**: **2 HIGH**, **6 MEDIUM**, **20 LOW** and **5 INFO** fixed in v1.2.3, plus three
optimizations. T-05, T-06, D-05, D-06 and SC-08 are confirmed and deliberately not fixed, with
reasons below. Suite **387 → 472** assertions, 165 → 194 tests.

Three things stand out, and all three are about earlier fixes.

- **Four fixes from 2026-08-26 were incomplete**, three of them HIGH. P-01 depended on an option
  other software sets (T-01, T-02). A-02 covered a child that lives but not one that will not
  finish dying (R-01). A-03 still compared a tree with itself (SC-02). A-05 checked input rather
  than output (T-03). All four had passing tests, and each test checked one case of the problem.
- **The adapters had no regression test at all**, and neither did the shipped binary. CI compiled
  `src/` into a test harness and never ran `cmdrs` (SC-03). A binary that segfaulted on its
  first line passed every gate.
- **Mutation testing caught the audit itself.** A-12's guard was verified by hand in August and
  never pinned, so removing it passed the suite.

---

## Threat model

Unchanged in shape from 2026-08-26: `cmdrs` runs on every prompt redraw, single process,
short-lived, not setuid. The attacker positions are a hostile project directory the user merely
`cd`s into, a co-tenant on the same host, and a hostile environment. The impact ceiling is
arbitrary command execution, through the shell glue rather than through `cmdrs` itself.

The list of repo-controlled inputs was out of date. It now reads: **the directory's own name**,
which is enough on the default config and is what makes T-01 and T-03 so reachable, then
`cyrius.cyml`, `VERSION`, `.python-version`, `.nvmrc`, `rust-toolchain`, `rust-toolchain.toml`,
and any `sit` branch or file name.

## Findings

### T-01 — the zsh adapter ran commands whenever anything set `prompt_subst` · HIGH

**Where**: [`adapters/zsh.sh`](../../adapters/zsh.sh), and the manual paste in
[`zsh-setup.md`](../guides/zsh-setup.md).

P-01 removed the adapter's own `setopt prompt_subst` and left the rendered bytes in `PROMPT`.
Nothing forced the option off, and `bash.sh` at least asserted its equivalent. With the option on
from any source, before or after sourcing, zsh expands `$(...)` in the finished string at every
redraw.

It is not an exotic state. zsh's own theme system sets it: `promptinit` themes use
`prompt_opts=(cr subst percent)`. oh-my-zsh is reported to as well, though that was not checked
here. The default `cwd` segment makes a directory name enough, so no probe file or custom config
is involved:

```
mkdir -p '/tmp/t/$(touch PWNED)'
# in a stock zsh with `autoload -Uz promptinit; promptinit; prompt adam2`, plus the adapter:
cd '/tmp/t/$(touch PWNED)'     →  PWNED is created, on every redraw
```

**Measured across both shells**: 8 payloads in 12 option states on real shells on a pty.
**31 of 96 cases executed a command** on 1.2.2. On 1.2.3, **0 of 96**, and every payload renders
as literal text.

**Fix**: the bytes no longer go in `PROMPT` at all. They sit in `$_cmdrs_left`, and `PROMPT` is the
fixed text `${_cmdrs_left}`. zsh expands that once and does not re-parse the value. The adapter
now turns `prompt_subst` **on** at every redraw, the reverse of P-01, and if something turns it
off the prompt shows the reference, which is ugly and safe. Same idiom as `git-prompt.sh`.
[ADR 0011](../adr/0011-prompt-holds-a-reference-not-the-bytes.md) has the alternatives.

The same change closes **T-09** (an exported `PS1` reaching a nested shell).

### T-03 — the C1 filter could be bypassed, and a repo could drive the terminal · HIGH

**Where**: [`src/color.cyr`](../../src/color.cyr), in both `sanitize_segment_output` and
`eprint_sanitized`.

A-05 dropped a `C2` followed by `80..9F`, by looking at the next **input** byte, and then deleted
C0 bytes from the **output**. Deleting a byte joins its neighbours:

| Input | 1.2.2 output |
|---|---|
| `c2 9b` | stripped, which is the only case A-05's test covered |
| `c2 01 9b` | `c2 9b` |
| `c2 7f 9b` | `c2 9b` |
| `c2 c2 9b 9b` | `c2 9b` |
| `c2 c2 c2 9b 9b 9b` | `c2 c2 9b 9b`, which still contains the pair |

`C2 9B` is U+009B, which a UTF-8 terminal that honours C1 reads as CSI. The filter was not even
idempotent. Over every string of up to five bytes on a 15-byte hostile alphabet, 1.2.2 broke the
invariant or idempotence 561,900 times across 813,615 strings.

**Proved end to end, on the default config, through both adapters, on real VTE 0.84.** A directory
named `repo\xc2\x01\x9d0;PWNED-TITLE\xc2\x01\x9c\xc2\x01\x9b2J\xc2\x01\x9b5;5H` set the window
title and cleared the screen. Query sequences made VTE write replies back to the pty as if typed:
`\x1b[1;2R` for DSR. VTE is GNOME Terminal, Tilix and xfce4-terminal. kitty and libvterm in UTF-8
mode ignore it, and libvterm in 8-bit mode acts on a raw `9B`. xterm and the Linux console were not
tested.

This is rated above A-05's MEDIUM because it is proven on a mainstream engine.

**Fix**: the filter now makes a promise about its output, and every branch keeps it: *no C0, no
DEL, and a byte in `0x80..0x9F` only inside a well-formed UTF-8 sequence for a code point at or
above U+00A0.* A `9B` can no longer survive alone, whether after a deletion or at the start of a
segment, and an overlong form's last byte is in that range too. Bytes `0xA0..0xFF` outside a valid
sequence stay, so a Latin-1 directory name still renders. One `_sanitize_bytes` now serves both
output paths, so they cannot drift apart. The limit on an 8-bit terminal is in *Known gaps*.

**T-07** was the same class across a seam: segment A ending in `C2` and segment B starting with
`9B` formed the pair between them, with `separator = ""` and no colour. Each segment is filtered
alone, and the rule above closes this too.

**Pinned by** an exhaustive test over all 813,615 strings, checking the invariant and idempotence.
Replayed through VTE: the capture contains no C1 sequence. An independent fuzz of hostile repo
files, checked with Python's decoder rather than ours, hits violations at once on 1.2.2 and found
**none in 60,000 runs** on 1.2.3.

### T-02 — the bash adapter ran commands in POSIX mode · MEDIUM

**Where**: [`adapters/bash.sh`](../../adapters/bash.sh).

P-01's `shopt -u promptvars` ran once at source time, and POSIX mode ignores the option:
`shopt promptvars` reports `off` and the command still runs. `set -o posix`, `bash --posix`,
or just `POSIXLY_CORRECT=1` assigned mid-session all brought back the execution, and so did a
later `shopt -s promptvars`.

**Fix**: as T-01, with `PS1='${_cmdrs_ps1}'`. Backslash decoding runs before expansion and sees
only the fixed text, so A-04's doubling of every `\` is gone too, and that attack is closed by
construction. Output is unchanged at 40 columns, including the `\001..\002` markers, which survive
expansion.

### R-01 — `waitpid` after `SIGKILL` had no deadline, so A-02 was still open · MEDIUM

**Where**: [`src/shellout.cyr`](../../src/shellout.cyr).

A-02 killed the child and then blocked in `waitpid`. `SIGKILL` is not synchronous, and a child stuck
in uninterruptible exit stays unreapable. A `sit` that opened a file on a FUSE mount whose daemon
never answered `FLUSH` parked `cmdrs` in `do_wait`, in the default config, with no attacker. A
ptrace helper held it for **6 s against a 5 ms budget**.

**Fix**: `_shellout_reap` tries `WNOHANG` five times over about half a millisecond, then gives up.
`cmdrs` exits a moment later and init collects the child. Replayed: `cmdrs` had exited at the first
sample, against 6 s before.

### SC-01 — dropping a module from the manifest exempted it from every lock guard · MEDIUM

**Where**: [`cyrius.cyml`](../../cyrius.cyml), [`scripts/lock-check.sh`](../../scripts/lock-check.sh).

`cyrius deps` checks only the footprint it derives from the manifest, and the manifest is in the
same commit. Three edits: drop `pwd` from `[deps].stdlib`, change `lib/pwd.cyr`, fix its lock line.

```
lock-check: OK — 2 dep pin(s), 117 locked file(s), matching a clean tag resolution
shipped binary with trigger: exit=77                    # 77 = the planted code ran
```

Every CI step passed and the release build shipped it. It needs a commit, and that commit could edit
`src/` instead. The gain is passing the guard whose job is exactly this, inside a bulk re-vendor diff.

**Fix**: `lock-check.sh` is replaced. It regenerates `lib/` and the lock from the pins in a throwaway
worktree of HEAD and compares them with what is committed. It reads no notes and does not parse the
manifest, so it cannot be argued with. Over 37 committed bad states it missed none, where the old CI
missed 14 and `cyrius deps --locked` alone missed 8. The full table is in
[architecture 003](../architecture/003-cyrius-lock-shape.md) § 5. This answers the seed-list question
of what CI should run.

### SC-02 — a deleted lock passed the guard, which removes the only tag-move defence · MEDIUM

**Where**: [`scripts/lock-check.sh`](../../scripts/lock-check.sh).

A-03's failure survived. `git cat-file` on a missing lock made the script fall back to the working
tree, which `cyrius deps` had just regenerated, so it compared a regeneration with a regeneration.
The 2026-08-26 report said this "cannot be defeated by reordering", and it did not need reordering.
A deleted lock plus a force-moved upstream tag put the moved code in a green build. Fixed by the same
replacement: no lock at HEAD is now a failure, with no fallback.

### SC-03 — CI never ran the binary it shipped · MEDIUM

**Where**: [`.github/workflows/ci.yml`](../../.github/workflows/ci.yml).

The suite compiles `src/` into a test binary, leaving out `main.cyr` and `render.cyr`. The bench times
`render_prompt` in-process. So a `cmdrs` that segfaulted on its first line, exited 42, or stalled for
200 ms all passed every gate, and the stall printed `OK: render_prompt 12.415us`. Removing the
sanitizer call from `render_prompt`, the audit's headline mitigation, also passed.

**Fix**: [`scripts/smoke.sh`](../../scripts/smoke.sh) runs `build/cmdrs` on hostile input and takes a
real cold start, and [`scripts/adapter-check.sh`](../../scripts/adapter-check.sh) proves the adapters on
real shells. The `--agnos` build now compiles in CI. The step misnamed "Cold-start budget gate" is
renamed. The 5 ms threshold in `smoke.sh` has not been seen on a real runner.

### SC-04 — the write token sat in `.git/config` while the release job ran an installer · MEDIUM

**Where**: [`.github/workflows/release.yml`](../../.github/workflows/release.yml).

A-09 took `contents: write` off the CI gate, but the job that kept it pipes a remote script to `sh` and
compiles. `actions/checkout` writes the token to `.git/config` by default, so every one of those steps
could read it, and `@v4` was a mutable tag on that job.

**Fix**: `persist-credentials: false`, and both checkouts pinned by SHA. softprops takes its token from
its own input, so it is unaffected. This was read from the actions' sources, and simulated with a fake
header. It has not run on a real runner.

### Optimizations

| ID | Finding | Result |
|---|---|---|
| **O-1** | **Transparent huge pages cost more than the whole render.** The allocator's 256 MB chunk is aligned to a huge page, so with THP set to `always`, the first heap touch zeroes 2 MB, and `args_init`'s 2 MB buffer moves the bump pointer into a second page. | See the table below. One `prctl`. |
| **O-2** | `rustup_env` walked once per file name, re-scanned the whole path for each `/`, and read a plain file twice. | One walk, one read. See the table below. |
| **O-3** | The bash adapter ran `sed` on every redraw. | **1,400 → 630 µs** per redraw. |

| Measured on this host, 3,000 interleaved pairs | 1.2.2 | 1.2.3 |
|---|---|---|
| Cold start, no config, THP `always` | 402 µs | **295 µs** (−27 %) |
| Cold start, largest theme, THP `always` | 611 µs | **485 µs** (−21 %) |
| Cold start, THP off in both | same | same, as a host on `madvise` sees |
| Cold start, `rust-toolchain` found deep in a tree, THP off | 505 µs | **446 µs** (−12 %) |
| Memory at exit | 4,272 KB | **204 KB** |
| Bash adapter, per redraw | 1,430 µs | **615 µs** (−57 %) |
| `rustup_env_render`, no file found, equal path depth | 33.1 µs | 29.7 µs (−10 %) |
| `render_prompt` | 12.41 µs | 12.25 µs (−1 %) |

A floor binary that does nothing takes about 190 µs here, so of 402 µs the program accounted for about
210 µs, and THP for half of that. **The O-1 gain applies only to hosts with THP set to `always`**, such as
Arch and Fedora. Debian and Ubuntu default to `madvise`, and see no change.

**Measured and left alone.** The roadmap suspected `config_load`'s 64 KB buffer and eleven
`_warn_nested_keys` sweeps. With THP off, a bump allocation touches nothing, so the buffer costs nothing
measurable. The sweeps cost 4.4 µs of 67 µs, about 1 % of a cold start, and merging them would reorder
warnings. Of the rest: read 4, CYML 9, TOML 18, defaults 3, and small linear lookups. There is no single
cause, and the largest piece is upstream. The two `/proc` reads for argv and env cost about 20 µs each, and
on Linux there is no other route to them from Cyrius.

## Seed-list decisions

**Cache eviction: replaced.** An entry can never be served once it is about 2 s old, so the useful cache
is a handful of directories. A file name is now one of 256 slots, with the full key inside the entry. A
directory sweep was prototyped and measured, and it would have worked, but it adds code that deletes
files under `/tmp` to a security release, to solve a problem a naming change removes.
[ADR 0012](../adr/0012-cache-bounded-by-construction.md).

**Config read cap (F-6): kept at 64 KB.** Lowering it would break configs the freeze protects, and the
numbers do not ask for it. The worst case is linear: 24 ms at 64 KB, and only the user's own file reaches
it. F-6's actual fear, a stack overflow on deep nesting, is gone: neither binary has any recursion (no
non-trivial SCCs in the call graph), and 32,500 brackets take 2.6 ms. What F-6's acceptance test asked
for, that an oversized file not half-load, is now true (D-03).

**`alloc` guards: fixed where it matters, not sprayed.** Fault injection covered all 46 sites, across
5,041 injected failures. Every crash was SIGSEGV on page 0, with no corruption. The one-buffer walk
removed the depth-scaled growth, and the size-scaled sites are guarded. What remains needs the user's own
hostile config plus a restrictive address-space limit, so 40 guards would be churn. The stated reason in
2026-08-26 was wrong, but its conclusion mostly stands. Corrected in *Known gaps*.

**Booting `--agnos`: done, for the first time.** A production kernel, real ext2, real agnsh, on QEMU, with
`cmdrs` typed at the prompt. See *Verified clean*.

**CI lock guard: replaced.** See SC-01.

## Verified clean

Claims that were tested and held.

**Memory.** No overflow, over-read, off-by-one or size-arithmetic bug in first-party code. 180,000+
fuzz iterations under poison-redzone and electric-fence builds, with three planted 1-byte defects
proving the fences work: 0 violations. Worst stack chain from entry is 14,296 B on the host and 6,928 B
on agnos. There is no recursion in either binary.

**`--agnos`, booted.** A production 1.57.17 kernel, gnoboot, OVMF, ext2 on NVMe, with agnsh 2.2.0 and
commands typed through the QEMU monitor. Left and right prompts, `--version`, `--help`, a bad flag, all
ten segments, a 5,000-element `segments` array, 32,500-deep bracket nesting, an over-cap config and the
largest theme: all correct, 0 fault lines in any serial log. `//.commandress` resolves.

**bayan, from the consumer side.** No recursion. Worst amplification 228×, bounded by the caps. Worst
parse of a 4 KB hostile file 567 µs. The per-process seed protects the dotted-key index. Decoding never
expands. A differential against Python's `tomllib` over 47,139 valid documents: 0 channel differences.
321,650 fuzz runs on the repo path, and a hostile repo cannot produce stderr output through it.

**cmdit, from the consumer side.** 72 hostile argv cases, all rc 0, nothing on stdout. No private symbol
used anywhere in `src/` or `tests/`. Arity is enforced by the compiler. Vendored files are byte-identical
to their tags.

**Provenance.** A rebuild from source equals GitHub's digest for the published `1.2.2/cmdrs`
(`c2fae27abb63…`) on both a scratch toolchain and a real tarball install. 113 `lib/` files equal the real
release tarball, and 3 equal the tags' `dist/`.

**Cache gate.** A real second UID against 0700 pre-create, 0777 pre-create and a symlink to a victim
0700 directory: the cache disabled and wrote nothing. That ran on 1.2.2 and was not rerun, and `cache_init`
is unchanged at 1.2.3. 720 concurrent cold starts: 0 bad on both.

**Adapters on the default config, in the default mode.** `%`, `\`, backticks and `$()` stayed inert
on 1.2.2, and do on 1.2.3.

**Workflow injection.** No `pull_request_target`, no `${{ }}` in a `run:` block except `concurrency`,
hostile tag names inert, softprops' SHA still equals `v2`.

**The filter.** `bench-gate.sh` is correct at the boundary. `read_regular_file` rejects directories,
`/dev/zero` and FIFOs. Exact caps have no off-by-one.

**Differential, 1.2.2 → 1.2.3.** 6,163 cases, 0 hangs, 242 differences, every one accounted for: 154 are
the new over-cap warning, on stderr, and 88 are one fixture, a `rust-toolchain` symlink to `/etc/passwd`
that used to print the password file into the prompt and now renders empty. Valid configs and ordinary
directories render byte-identically.

## Confirmed but deliberately not fixed

- **T-05: probe files follow symlinks.** `ln -s ~/.ssh/id_ed25519 .python-version` shows up to 256 bytes
  of any file the user can read, with control bytes removed. There is no return channel, so this matters
  for recorded or shared sessions. `O_NOFOLLOW` would blank legitimate monorepo pins (`.nvmrc ->
  ../.nvmrc`) and `~/.commandress` from a dotfile manager. A content-shape rule is the better fix, and it
  belongs with the length cap at roadmap 1.5.0. `rust-toolchain` already refuses a multi-line target (D-01).
  > **Update 2026-11-06** (annotation, not a revision): closed at 1.5.0, and not by a content-shape rule, which
  > cannot refuse a one-word token because a pin may be any bare word. A symlinked pin must now end at a file of
  > the same name. `/proc/self/environ` was reachable the same way and is not listed above. See
  > [ADR 0015](../adr/0015-pins-keep-their-name-and-shape.md).
- **T-06: the walk accepts files owned by another user.** A co-tenant's `/tmp/.python-version` applies
  under `/tmp`. With T-03 closed it is inert text, and it gives a co-tenant nothing a hostile directory
  does not. An owner check would blank pins in shared checkouts and containers. Pinned with T-05.
  > **Update 2026-11-06** (annotation, not a revision): stands at 1.5.0 on purpose, and it is now a word of at
  > most 64 characters. See [ADR 0015](../adr/0015-pins-keep-their-name-and-shape.md).
- **D-05: `--bogus --side=right` renders the left prompt.** A-07 reads flags parsed before the error, and
  cmdit stops at the first bad token. No adapter can produce that order, and a local fix means re-entering
  the parser. The clean fix is a continue-on-error mode in cmdit.
- **D-06: cmdit's stderr escaper passes C1.** Argv is not an attacker position, and both adapters pass a
  fixed argv. Upstream.
- **SC-08: the released binary is a second build, not the one CI tested.** The build is reproducible and
  verified, and each job now runs the lock guard. Moving it to an artifact needs a two-job split that
  cannot be tested without a real runner.
- **`find_in_path` stops at a non-runnable hit.** A directory named `sit` earlier on `PATH` ends the
  lookup. It costs one `stat` on the hot path to fix a rare setup, and retiring this file is on the roadmap.
- **Budget granularity.** Millisecond truncation makes the effective budget up to 1 ms short. The default
  of 5 rendered 400 of 400, and `budget_ms = 1` with a 0.3 ms `sit` rendered 332 of 400.
- **A hostile `sit` on `PATH`.** It can leave a background child behind, drain the pipe between `epoll`
  and `read`, or `SIGSTOP` its parent. If an attacker controls `PATH` they already have what these give.
- **Render amplification from your own config.** 64 KB of `time` segments can render 147 MB in 1.2 s.
  Trusted file, and the same reasoning as F-6.
- **The smallest stacks and heaps.** `ulimit -s 16` faults in `vcs_render`'s 12 KB frame. `ulimit -v 12000`
  makes `alloc_init` exit 1 with an empty prompt. Neither is an attacker position, and the second is stdlib.

## Known gaps, stated rather than hidden

- **Real CI has not run this.** No step was run on a GitHub runner. `actions/checkout`'s behaviour was
  read from its source, the steps were rehearsed in a fresh clone, and `smoke.sh`'s 5 ms threshold is
  unvalidated on a runner.
- **`thp_opt_out()`'s position in `main` is not pinned.** The call is tested, and its effect was measured
  once (below), but `main.cyr` cannot be included in a test. Moving it after `alloc_init` would pass CI.
- **Two guards have no unit test**, because they need heap exhaustion: `time_format`'s two returns and
  `_section_pairs`'. The first was replayed under `RLIMIT_AS`.
- **A hostile repo can still put text into the prompt.** Sanitized and inert, but up to 255 bytes from a
  probe file, 8,182 from a `sit` branch, 4,095 from `cwd`, and whatever length `VIRTUAL_ENV` has. Roadmap 1.5.0.
  > **Update 2026-11-06** (annotation, not a revision): since 1.5.0 a pin is at most 64 bytes, and `vcs` and the
  > language segments stop at 128 by default. `cwd` keeps its frozen default of no limit. See
  > [ADR 0015](../adr/0015-pins-keep-their-name-and-shape.md).
- **Unprintable lookalikes pass.** U+202E, U+2066, U+200B, U+2028, U+FEFF and tag characters are valid
  UTF-8 and pass. On kitty they drew as glyphs or replacement characters, with no control effect, but a
  bidi override could reorder what a bidi-aware terminal shows.
- **An 8-bit terminal.** A bare `9B` is stripped, but real UTF-8 text keeps its continuation bytes:
  `C4 9B` is the letter U+011B, and an 8-bit terminal reads its second byte as CSI. pyte in 8-bit mode
  cleared the screen on those bytes from a `.python-version`. Both cannot be kept, and UTF-8 is the
  case that matters.
- **`prompt_bang`.** With that zsh option on, `!` in a value becomes the history number. Cosmetic.
- **Terminals not tested**: xterm and the Linux console. Multibyte locales where `\` can be a trail byte
  (Shift-JIS, Big5) are not installed here. The bash wrap's patterns are ASCII after ESC, which no multibyte encoding uses as a lead byte.
- **A BOM** at the start of `~/.commandress` silently loses the first table.
- **`cyrius build --aarch64` fails** on undefined `SYS_ACCESS`, unrelated to this release. aarch64 is not a
  CI target, and `src/cache.cyr` is x86_64-specific.
- **Tag mutability** in P-07's fix stands, as noted there.
- **agnos renders no `cwd`.** See the agnoshi adoption item in the [roadmap](../development/roadmap.md).

## Next audit

Trigger points: a new segment that copies external bytes, any change to `_sanitize_bytes` or the render
chokepoint, a new adapter (add it to `scripts/adapter-check.sh`), a cmdit or bayan pin bump that changes
its public surface, a cached segment with a longer TTL, or a config-schema addition that introduces a new
trusted-input path.

The lesson from this pass to carry into that one: **test what a fix promises, and not only the attack
that prompted it.** P-01 tested one option state, A-05 one byte spelling, A-02 one way of not dying, and
A-03 one step order. Every one of those tests passed, and every one was testing an instance rather than
the property. Prefer an invariant that can be checked on the output, and a mutation run to prove the check
can fail.
